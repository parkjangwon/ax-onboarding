# [Runbook 01] 서버 장애 및 스택 트레이스 긴급 분석

이 런북은 서비스 운영 중 발생한 오류나 장애 로그를 에이전트와 함께 안전하고 신속하게 분석할 때 사용합니다.

## 실행 규칙 (Security & Safety)
1. **READONLY 원칙**: DB 쿼리는 오직 SELECT만 수행하며, 데이터 변경은 금지합니다.
2. **비밀정보 마스킹**: 로그 확인 시 주민번호, 비밀번호, API Key 등 PII/Secret이 출력되지 않도록 확인합니다.
3. **추측 금지**: 반드시 로그 라인 번호, 파일명, DB 레코드 값 등 구체적 증거를 기반으로 분석합니다.

## 에이전트 자율 실행 절차 (Autonomous Execution Flow)
사용자가 "배치 죽었어", "에러 났어", "로그 좀 봐줘"와 같이 일상어로 요청하면, 에이전트는 사용자가 런북을 언급하지 않아도 아래 절차에 따라 자율적으로 수행합니다:

1. **로그 수집**: SSH MCP 또는 로컬 로그 파일에서 장애 발생 시간대의 ERROR / WARN 스택 트레이스를 추적합니다.
2. **코드 특정**: 오류가 발생한 프로젝트 소스코드의 파일명과 라인 번호를 정확히 식별합니다.
3. **원인 분석**: 비즈니스 로직 결함, DB 데이터 정합성 문제, 혹은 외부 연동 예외를 분석합니다.
4. **패치안 제시**: 기존 기능에 부작용을 주지 않는 최소한의 보수적 방어 코드(Null check, try-catch, 롤백 등)를 제안합니다.

> 💬 **사용자 발화 예시**: "어제 15시경에 배치 돌다가 에러 났다는데 로그 확인해서 원인 좀 찾아줘."
