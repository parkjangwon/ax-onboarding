# [Runbook 01] 서버 장애 및 스택 트레이스 긴급 분석

이 런북은 서비스 운영 중 발생한 오류나 장애 로그를 에이전트와 함께 안전하고 신속하게 분석할 때 사용합니다.

## 실행 규칙 (Security & Safety)
1. **READONLY 원칙**: DB 쿼리는 오직 SELECT만 수행하며, 데이터 변경은 금지합니다.
2. **비밀정보 마스킹**: 로그 확인 시 주민번호, 비밀번호, API Key 등 PII/Secret이 출력되지 않도록 확인합니다.
3. **추측 금지**: 반드시 로그 라인 번호, 파일명, DB 레코드 값 등 구체적 증거를 기반으로 분석합니다.

## 에이전트 지시 프롬프트

```text
@runbooks/01-troubleshoot.md

[상황 공유]
- 발생 일시: {발생 시각, 예: 오늘 15:30경}
- 대상 서비스/모듈: {서비스명 또는 IP/도메인}
- 증상 요약: {예: 500 에러 발생, 배치 작업 중단, 특정 계정 로그인 실패}

[요청 사항]
1. SSH MCP 또는 제공된 로그에서 해당 시간대의 ERROR / WARN 스택 트레이스를 추적해줘.
2. 오류가 발생한 프로젝트 소스코드의 파일명과 라인 번호를 정확히 식별해줘.
3. 원인이 되는 비즈니스 로직 결함, DB 데이터 정합성 문제, 혹은 외부 연동 예외를 분석해줘.
4. 기존 기능에 사이드 이펙트를 주지 않는 최소한의 방어 코드(Null check, try-catch, 트랜잭션 롤백 등) 수정안을 제안해줘.
```
