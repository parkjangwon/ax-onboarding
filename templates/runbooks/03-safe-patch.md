# [Runbook 03] 보수적 코드 패치 및 GitLab/GitHub MR 생성

운영 중인 서비스나 패키지 솔루션의 안정성을 해치지 않고, 하위 호환성을 유지하며 최소 범위로 코드를 수정할 때 사용합니다.

## 핵심 가드레일 (Ground Rules)
1. **과도한 리팩토링 엄금**: 요청받은 결함이나 기능 외에 다른 클래스나 구조를 자의적으로 리팩토링하지 않습니다.
2. **하위 호환성 유지**: 기존 DB 스키마, 파라미터 시그니처, 설정 파일 키를 변경하지 않고 확장합니다.
3. **사내 형상관리 규칙 준수**: 이슈 번호 브랜치 명명 및 커밋 메시지 컨벤션을 준수합니다.

## 에이전트 자율 실행 절차 (Autonomous Execution Flow)
사용자가 "버그 수정해줘", "이 기능 안전하게 고쳐줘"라고 요청하면, 에이전트는 아래 원칙에 따라 최소 범위로 코드를 수정합니다:

1. **최소 범위 특정**: 수정이 필요한 최소한의 파일과 메서드 범위를 먼저 확인합니다.
2. **보수적 패치**: 기존 시스템의 동작이나 하위 호환성을 해치지 않는 최소한의 방어 코드를 작성합니다.
3. **단위 테스트 검증**: 수정한 부분에 대한 검증 시나리오를 실행하여 기존 기능의 무결성을 확인합니다.
4. **MR/PR 초안 완성**: GitLab/GitHub에 바로 제출할 수 있는 머지 리퀘스트 설명(배경, 변경점, 검증 결과)을 작성합니다.

> 💬 **사용자 발화 예시**: "메일 수신 시 특수문자 파싱 에러 나는 부분 다른 코드 건드리지 말고 안전하게 고쳐줘."
